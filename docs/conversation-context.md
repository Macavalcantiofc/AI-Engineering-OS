# 🧠 Conversation Context

> Contexto operacional curto para retomada. **Não é fonte de verdade.**

## Estado atual

Estamos estruturando o AI Engineering OS como um sistema pessoal de aprendizagem contínua. A conversa gera conhecimento; o GitHub registra apenas aquilo que decidimos preservar.

## Tema em exploração

A cadeia de fundamentos de AI Engineering:

`documento → chunking → embeddings → vector store → retrieval → RAG → contexto → LLM → tool calling → MCP → agent`

O foco é compreender o problema, a abstração, a arquitetura, os trade-offs e o momento correto de uso de cada camada, antes de sair implementando.

## Como trabalhamos

- Conceitos antes de ferramentas.
- Questionar o raciocínio, não apenas entregar respostas.
- Diferenciar fato, inferência, hipótese e opinião técnica.
- Pesquisar quando atualidade ou evidência externa for importante.
- Evitar transformar cada descoberta em documentação.
- Usar experimentos quando eles aumentarem a evidência.

## GitHub

O GitHub é a fonte de verdade do OS.

Fluxo aprovado para mudanças:

`diagnóstico → proposta → branch → PR → revisão humana → merge`

O `main` representa o estado oficial. O usuário faz o merge final.

## Continuidade

Este arquivo existe para evitar que uma retomada comece completamente do zero. Ele deve permanecer pequeno e operacional. Conhecimento durável deve ser promovido para os artefatos apropriados do OS.

## Próximo passo

Começar pelo fundamento da cadeia: entender por que particionamento, representação vetorial, indexação e recuperação existem antes de estudar RAG como arquitetura.

## Nota

Se este arquivo crescer demais, ele está fazendo o trabalho errado. O objetivo é contexto de retomada, não memória infinita.
